# Переработка и проверка сопровождаемости

## Границы проверки

Работа от исходного `main` `89bc0c5`: проверены архитектурные границы server,
расширения, shared-контракта, хранения состояния и инфраструктуры; выполнены
статические проверки всего проекта и оба набора автотестов. Углублённая проверка
и изменения сосредоточены на HTTP, JSON persistence, браузерной сессии, popup и
выборе каталога systemd. Это не утверждение об отсутствии дефектов во всём коде.

Публичные сигнатуры клиентов, CLI-коды, формат саммари и sync-index сохранены.
Сервер остаётся summary-only. Shared sync-решения не перенесены в потребителей.
Fallback rich → text → edit в Telegram сохранён вместе с регрессионными тестами.

## Изменения и основания

- Popup разделён на отображение, опрос и действия. Опрос не создаёт параллельных
  запросов, ограничивает ожидание и игнорирует поздние ответы после остановки.
  При закрытии снимаются обработчик runtime и таймеры экспорта.
- Интерпретация сессии работает с одним снимком storage; DOM handshake отделён.
  Убран кэш page-token между вызовами, проверен выход из аккаунта. Ошибка вставки
  скрипта и таймаут освобождают слушатель сообщения.
- Повторы запросов API и саммари расширения используют одну политику. Таймаут
  действует до чтения JSON/текста, а не только до получения HTTP-заголовков.
  Некорректный JSON успешного ответа расширения теперь даёт явную ошибку.
- Серверные клиенты internal/official API используют общий механизм таймаута
  до конца чтения тела. Существующие классификация auth и политики повторов сохранены.
- Временные JSON создаются сразу с ограниченными правами; новые директории —
  с `0700`. При неудачной записи/переименовании временный файл удаляется,
  исходная ошибка сохраняется. Конкурентные записи дают целый JSON.
- Выбор systemd checkout отделён от SSH и мутаций. Явный путь, затем путь unit
  имеют приоритет над историческими каталогами. Автообнаружение принимает только
  единственный каталог с `.env` и признаками Plaud; неоднозначность завершает preflight.

## Тесты и стоимость сопровождения

Проверка Telegram по строкам исходника и проверка длины текста заменены вызовом
реального dispatcher: ошибка sync должна вызвать alert; сбой ответа Telegram
не должен выходить наружу. Тест финализатора больше не выдаёт проверку успешного
callback за проверку timeout: добавлены отдельные сценарии timeout и cancel.

Проверки выбора checkout выполняются на временных каталогах. Статические проверки
порядка destructive-операций деплоя сохранены. Тесты shared-контракта между двумя
средами не считаются ненужными дублями и не удалены.

Добавлены сценарии API, саммари, audio URL, авторизации, исчерпания повторов,
зависшего тела HTTP-ответа, lifecycle popup и logout. Обычные тесты используют
подменённые API; smoke запускает реальный Chromium с локальным HTML и Chrome API
фикстурами. Внешние запросы браузера блокируются.

Coverage сохраняет прежние пороги и требует новые модули в LCOV. Для popup
добавлен отдельный порог: 70% строк, 60% ветвей, 75% функций. Процент строк до
и после переносов нельзя сравнивать как единственное доказательство улучшения.

## Проверка и ограничения

- `npm run check`: lint, типы, форматирование, Markdown, imports/manifest,
  оба набора тестов, import smoke и тесты инфраструктуры.
- `npm run test:coverage`: LCOV, пороги, присутствие обязательных модулей.
- `npm run test:browser`: offline Chromium smoke; перед первым запуском
  `npx playwright install chromium`. В CI браузерный smoke выполняется на Node 24.
- `bash scripts/docker-smoke-image.sh`: сборка и smoke контейнера.
- `actionlint`, `shellcheck`, `hadolint`: инфраструктурная проверка.

Браузерный smoke не заменяет живую проверку Plaud, системной загрузки Chrome,
приостановки MV3 service worker или Safari. В этой работе реальные пользовательские
sync, auth и выгрузки не запускались. Существующие серверные boundaries, tree browse,
scheduler и Telegram transport проверены регрессионными тестами; их широкая
перестройка не дала бы подтверждённой пользы и не выполнялась.
